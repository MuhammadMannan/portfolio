## Overview

Every team in the sales org tracked MBOs differently, in PDFs, Excel sheets and Word docs. I designed and built MBO Tracker, a desktop app that puts objectives, payout progress and AI coaching in one place.

## The problem

- **ELHs** switched between files to answer "Where am I?" and "What will I earn?"
- **Managers** spent one-on-ones rebuilding status instead of coaching.
- **Compensation data** is sensitive, so it had to stay on the user's machine.

## 1. Local AI that non-technical users can set up

The AI runs on the user's own computer, and most salespeople have never installed an AI model. Setup moved from a README, to a link, to a guide inside the app, so nobody has to leave the product.

<Figure src="/images/work/mbo-tracker/07-setup-onboarding.webp" width={2400} height={3072} alt="The AI setup guide showing Ollama not detected, two Granite model options and three setup steps" caption="Plain-language hardware advice, a recommended default, three steps, and a way to check again or skip." />

Skipping costs nothing. The app works fully without AI, and the same guide stays on the dashboard for later.

<Figure src="/images/work/mbo-tracker/08-setup-dashboard.webp" width={2400} height={2041} alt="The AI performance summary section with the setup guide below it" caption="Once AI is ready, a coaching summary is one click away." />

## 2. AI suggests, the user decides

Users import the spreadsheet they already have. Granite maps its columns to the app, and nothing is imported until the user has reviewed every match.

## Designing in code

I designed directly in code with IBM Bob, so my team tested a working product, not a prototype. Moving from plain React to Carbon changed how the app works:

- Updating progress became one focused question, with the target locked.
- Status changes moved into a one-click row menu.
- Every dialog follows the same layout, so learning one teaches them all.

<Figure src="/images/work/mbo-tracker/16-update-progress.webp" width={2400} height={1505} alt="Update progress dialog with a number input, a locked target and a live progress bar" caption="One question, a locked target and a live preview before saving." />

## Testing

I tested with my team of 12, including my manager. One teammate installed Ollama but got stuck downloading the model, because Ollama's site doesn't explain that step. I made it its own step with the exact command to copy.
